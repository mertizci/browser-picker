Quick start

  1. Open Settings → Rules → Add Rule, or edit an existing rule.
  2. Under Match conditions, choose Any (OR) or All (AND).
  3. Choose a condition type from the dropdown and enter its value. Use Add Condition for another condition, or the minus button to remove one.
  4. Check NOT to invert an individual condition.
  5. Choose an enabled browser profile and click Save Rule.

Rules run in list order: the first matching enabled rule wins. Disabled rules and rules targeting disabled profiles are skipped. If no rule matches, your configured fallback handles the link.

Test a URL without opening it

  1. Save your rule, then find Rule tester at the top of Settings → Rules.
  2. Paste a full URL, such as https://example.com/work/project. Include https:// or http://.
  3. Optionally choose a Source application to simulate a link sent by that app. Leave it as Unknown / not provided to test without source information.
  4. Click Test Rule or press Return. The result shows the first matching saved rule, the browser and profile, and the space when applicable.

Disabled rules and rules targeting disabled profiles are skipped, just as when opening a real link. If no rule matches, the result explains whether your menu bar selection would be used or the browser picker would open. If a matched rule’s profile is missing, update its destination; routing would fail instead of falling back.

The tester never opens the link or changes your settings. It previews the routing decision; it does not check browser launch permissions. A missing saved space uses the current space. Changing the URL, settings or detected profiles clears the result: click Test Rule again to refresh it.

Condition types

ConditionWhat it checks
URL containsText anywhere in the full URL, including query parameters and fragments. Case-insensitive. Example: project=work.
Host equalsThe exact hostname, without scheme, port or path. Case-insensitive. example.com does not match docs.example.com.
Host suffixA hostname ending in the supplied text, ignoring case and optional leading/trailing dots. This is a literal suffix: example.com also matches notexample.com. For a domain and its subdomains only, use the regex example below.
Path equalsThe entire decoded path, including trailing slashes. /dashboard matches https://example.com/dashboard?tab=work, but not /dashboard/.
Path starts withA decoded path beginning with the value. /work/ matches /work/report, but not /workspace or /work.
Path containsText anywhere in the decoded path. /invoices/ matches /accounts/invoices/42.
URL regexA regular expression searched against the full URL, including its query and fragment. Case-sensitive by default. See the examples below.
Source applicationThe macOS application that sent the link. Click Choose Application… and type to filter installed apps by name or bundle identifier. Select a result with its icon, or use the arrow keys and Return. The rule saves the app’s bundle identifier, so renaming or moving an app does not change the match.

Path conditions ignore the domain, query string and fragment. They are case-sensitive: /Work/ differs from /work/. Path equals and Path starts with must begin with /. A URL with no path is treated as /.

Paths decode percent escapes: enter /my files/ to match a path containing /my%20files/. URL contains and URL regex use the full URL representation, so use percent-encoded text there when appropriate.

AND, OR & NOT

  • Any (OR): at least one condition must match. Use this for several alternative domains.
  • All (AND): every condition must match the same link. Use this for a particular domain and path.
  • NOT: inverts only the condition beside the checkbox. A matching path becomes an exclusion; the other conditions keep their own meaning.

To restrict a domain and exclude a path, choose All (AND). With OR, a NOT condition can match most links outside that path, even on other domains.

The selected mode applies to the whole condition list. Nested groups such as (A OR B) AND C are not supported in a single rule; use separate rules for each domain with the same exclusion.

Examples

Work links from Mail

Mode: All (AND)
Source application: Mail
Host equals: example.com

Only links to this domain sent by Mail open in the chosen work profile. Use Any (OR) with several source application conditions to match links from any of those apps.

Source information comes from the sending macOS event. Some apps open links through helpers or intermediaries, and some senders cannot be identified. An unknown source matches neither a Source application condition nor its NOT version. URL-only rules and your fallback still work. The frontmost application is not used as a guess.

Two work domains

Mode: Any (OR)
Host equals: gitlab.example.com
Host equals: jira.example.com

Either domain opens in the selected work profile.

Only the work section

Mode: All (AND)
Host equals: example.com
Path starts with: /work/

Matches https://example.com/work/report. Does not match https://other.com/work/report or https://example.com/personal/.

A domain except its personal section

Mode: All (AND)
Host equals: example.com
NOT Path starts with: /personal/
NOT Path equals: /personal

Both exclusions are needed to cover the section itself and everything beneath it. Other domains do not match.

Regular expressions

Choose URL regex and enter the pattern directly. Do not wrap it in JavaScript-style /pattern/ delimiters. Browser Picker uses Foundation’s NSRegularExpression syntax.

A pattern can match part of the URL. Use ^ to anchor its beginning and $ for the end. Escape literal dots as \.. Add (?i) at the beginning for case-insensitive matching.

Work or admin section on one domain

^https://example\.com/(work|admin)(/|[?#]|$)

Matches https://example.com/work/report and https://example.com/admin?tab=users, but not https://example.com/workspace.

A domain and its subdomains

(?i)^https?://([a-z0-9-]+\.)*example\.com(:[0-9]+)?(/|[?#]|$)

Matches example.com and docs.example.com, including an optional port. Does not match notexample.com.

PDF links

(?i)\.pdf([?#]|$)

Matches a full URL ending in .pdf, optionally followed by a query or fragment. Since regex checks the entire URL, this can also match text inside a query value.

Invalid expressions show an error in the editor and cannot be saved. Expressions that fail or are interrupted for taking too long are treated as non-matches, even with NOT.

Why did my rule not match?

  • Check that both the rule and its destination profile are enabled.
  • An earlier rule may already match the link. Drag rules to change their priority.
  • Two different Host equals conditions cannot both match one link under AND; use OR.
  • Check path case and trailing slashes. Path conditions do not look in query parameters.
  • Every condition needs a valid value. A new empty condition keeps Save Rule disabled until filled or removed.
